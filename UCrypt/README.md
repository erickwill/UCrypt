## The Hard Truth About Sync (Be Informed)

**Cross-device sync over the internet REQUIRES a server somewhere.** No server = no way for devices on different networks to find each other. This is physics, not software.

### What Brave Does
Brave runs their **own sync server** (`sync.brave.com`) — a dumb relay that stores encrypted blobs. The sync code (24-word mnemonic) is the encryption key. The server only sees ciphertext. But the server MUST exist.

### What We Do (Multi-Transport — No Lock-In)
We don't run a server. Instead, we support **multiple transports** so you pick whatever you have:

| Transport | Requires | Works On | Setup |
|-----------|----------|----------|-------|
| **chrome.storage.sync** (automatic first hop) | Chrome + Google account | Chrome only | Zero config |
| **Google Drive** (Apps Script bridge) | Your Google account | All browsers | Paste a script, ~3 min |
| **Dropbox** | Access token | All browsers | Create app → paste token |
| **GitHub Gist** | "gist"-scoped token | All browsers | Create token → paste |
| **WebDAV** | Your own server (Nextcloud…) | All browsers | Paste URL |
| **Custom URL** | Any PUT/GET endpoint | All browsers | Paste URL |
| **Manual export** | Nothing — just a file | All browsers | Export → copy → import |

**The sync code (24-word mnemonic) works across ALL transports.** The vault is encrypted BEFORE it touches any transport. Every server/relay only ever sees ciphertext.

### Sync Cadence (v2.8.0 — when does data actually move?)

| Direction | When | Notes |
|-----------|------|-------|
| **Push → cloud** | Immediately on EVERY vault change | save, edit, delete, TOTP add/remove, bulk import — one encrypted push per change |
| **Push → cloud** | Automatic retry every 15 min + at next unlock | if a push failed (offline, 5xx, token expired) or the MV3 worker died mid-upload — the `ucrypt:lastPush` ledger knows what never landed |
| **Pull ← cloud** | At every unlock | the moment your sync key exists, peers' changes merge in (per-entry LWW + tombstones) |
| **Pull ← cloud** | Every 15 minutes (alarm) | mid-session changes from other devices arrive without manual syncs |
| **Pull ← cloud** | On chrome.storage.sync changes (debounced 1.5 s) | instant for the built-in Chrome/Edge first hop |
| **Both** | Manual "Sync now" / "Pull from cloud" | Sync tab + popup, whenever you want |

Every push outcome is recorded (`ok`, timestamp, transport, error) and shown in the Sync tab ("Last cloud push") and the popup ("Cloud push") — no silent failures, no false "pushed!" claims. Restoring a sync code on a fresh device **pulls first and never overwrites the cloud copy with an empty vault**.

```
Ciphertext only — every hop stores AES-GCM blobs that only the sync code can open.
```

### Two Keys, Two Purposes (Defense in Depth)

| Key | Derived From | Protects |
|-----|-------------|----------|
| Master Key | Master passphrase | Local vault (chrome.storage.local) |
| Sync Key | Sync code (24-word mnemonic) | Cross-device sync blob (all transports) |

If ANY transport is compromised → attacker gets ciphertext → can't decrypt without the sync code.
If the sync code is compromised → attacker can decrypt the sync blob → but still needs the master passphrase for the local vault.

## Quick Start

### Step 1: Load the Extension
1. Open `chrome://extensions` (or `brave://extensions`, `vivaldi://extensions`, etc.)
2. Enable **Developer mode**
3. Click **Load unpacked** → select the `ucrypt-extension/` folder

### Step 2: Set Up the Vault
1. Click the UCrypt toolbar icon
2. Click **"Set up master passphrase"**
3. Enter a strong passphrase (min 8 chars, recommend 12+)
4. Your vault is now encrypted locally

### Step 3: Enable Cross-Device Sync
1. Right-click UCrypt → **Options** → **Sync** tab
2. Click **"Generate Sync Code"**
3. You'll see 24 words + a QR code
4. **Write down the 24 words** — this is the ONLY recovery method
5. Choose your transport (your-own-cloud law — UCrypt never runs a server):
   - **chrome.storage.sync** — if on Chrome with a Google account (automatic, zero config)
   - **WebDAV URL** — if you have your own server (paste URL)
   - **Google Drive / GitHub Gist / Dropbox** — your own account, connected via OAuth (the Connect button); the grant is sealed device-only
   - **Manual** — export encrypted .json → copy to other device → import
6. On your other device: enter the 24 words → same key → auto-sync

### Step 4: Migrate from another browser or password manager (optional)
1. Export from your old browser/manager (every source has step-by-step
   instructions inside the Import Center):
   - **Chrome / Edge / Brave / Vivaldi / Opera**: *Settings → Passwords → ⋮ → Export passwords* (CSV)
   - **Firefox**: *about:logins → ⋯ → Export Logins* (CSV or JSON)
   - **Bitwarden / LastPass / 1Password / Dashlane / KeePassXC / RoboForm / NordPass / Enpass**: File → Export (unencrypted CSV/JSON)
   - **Bookmarks**: Bookmark manager → Export to HTML
2. UCrypt → Options → **Export / Import** → **Import Center** → pick the
   source → drop the file
3. Review the preview (logins, 2FA seeds, notes, cards, identities,
   bookmarks, history, form data) → **Import selected**
4. Duplicates and conflicts are skipped and listed — existing entries are
   NEVER overwritten (enforced twice: in the plan and again at save time)
5. If a cloud transport is configured, the encrypted vault (with everything
   imported) is pushed automatically — the report shows the transport status

## Security Model

- **No UCrypt accounts** — no email, no signup, no telemetry. Cloud sync connects to YOUR OWN cloud (WebDAV / Google Drive / GitHub Gist / Dropbox) with OAuth grants you create and can revoke — every grant is sealed device-only, never uploaded, dropped on lock, cleared on Disconnect
- **No remote code** — all JS bundled, CSP `script-src 'self'`
- **No plaintext at rest** — everything AES-GCM encrypted before any storage
- **No plaintext in transit** — sync blob is encrypted before it touches any transport
- **No identity leak** — UCrypt runs no server; the sync code is your only credential, and your cloud provider sees only AES-GCM ciphertext
- **Defense in depth** — separate master key (local) + sync key (cross-device)
- **No lock-in** — use any transport, switch anytime, the sync code works everywhere

## Upgrading from a pre-2.46.0 unpacked install — the extension ID change (read this once)

**What changed.** Starting with v2.46.0, UCrypt ships a **pinned extension identity** (a `key` in manifest.json, introduced in v2.45.0). Chrome derives the extension ID from that key instead of from the install path. For every install that loads UCrypt from the store or a packed CRX this is invisible; for an **unpacked** ("Load unpacked") install of an EARLIER version, updating to v2.46.0 makes Chrome treat it as a brand-new extension with a NEW ID:

- old (path-derived) ID: `glbjnfimcajjenihimblfaponejbkoph` (example — derived from your folder path)
- new (pinned) ID: `flnkienipfckfekonogdlgphdacokpoa` — the SAME on every machine, forever

**Why.** The pinned ID keeps UCrypt's OAuth redirect URI byte-stable everywhere:

```
https://flnkienipfckfekonogdlgphdacokpoa.chromiumapp.org/
```

That exact URL is what you paste into Google Cloud Console (Drive OAuth), and what GitHub/Dropbox OAuth apps may reference. Without the pin, every machine (and every folder move) produced a different redirect URI — the root cause of the Drive "Error 400: redirect_uri_mismatch".

**The recovery path (your data is safe).** Your vault lives in YOUR cloud storage, sealed. Nothing was lost:

1. Load/unpack v2.46.0 (Chrome now shows it under the new pinned ID).
2. Set any master passphrase and unlock (the fresh local shell starts empty).
3. Cloud Sync → **"I already have one"** → re-enter your 24-word sync code.
4. Reconnect the **SAME** cloud storage (Drive / Dropbox / GitHub Gist / WebDAV) — the transport you used before.
5. Pull. The vault returns from the cloud intact (entries, TOTP seeds, identities, history).

**What does NOT migrate:** data the BROWSER itself saved under the old ID (its own password-store entries, UCrypt's local display preferences). The browser's own passwords are the browser's — export them from `chrome://settings/passwords` if you want them in the vault (Import Center → Chrome CSV).

The in-product reminder (Options → top of the Vault tab) is a one-time note that closes **only** when you acknowledge it — it never times out and never auto-dismisses.
